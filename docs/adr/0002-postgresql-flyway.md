# ADR-0002: PostgreSQL مع Flyway

- **الحالة:** مقبول
- **التاريخ:** 2026-11

## السياق
نحتاج قاعدة علائقية، ومخططًا يتغير مع الوقت بأمان.

## القرار
PostgreSQL كقاعدة وحيدة. المخطط يُدار بـ **Flyway** فقط (`V1__init.sql` ثم `V2__...` وهكذا) و`ddl-auto: none`.

## البدائل
- **MySQL 8:** صالح ويعمل بعد تعديل بسيط في المخطط. اخترنا PostgreSQL لتطبيقه الفعلي لقيود `CHECK`، ودعمه `TIMESTAMPTZ` و`FILTER`، و`JSONB` لنتائج الذكاء الاصطناعي لاحقًا. يمكن العودة إليه إن كانت خبرة الفريق أو الاستضافة تفرض ذلك.
- **Hibernate ينشئ الجداول:** مرفوض لأنه يخفي تاريخ التغييرات.

## النتائج
- (+) كل تغيير في المخطط ملف مسجّل.
- (-) **لا نعدّل `V1` بعد تشغيله على أي بيئة**، نضيف ملفًا جديدًا فقط.
- (-) الكيانات تُكتب يدويًا بما يطابق المخطط، وأي اختلاف يظهر عند التشغيل.
