# ADR-0001: Modular Monolith بدل Microservices كاملة

- **الحالة:** مقبول
- **التاريخ:** 2026-11

## السياق
المشروع يخدم مدرسًا خصوصيًا بعدد مستخدمين صغير، ويبنيه شخص واحد. طُرحت فكرة Microservices.

## القرار
نبني **تطبيقًا واحدًا مقسَّمًا لوحدات** (حزمة لكل ميزة). ونؤجل فصل خدمتين فقط حتى يظهر سبب حقيقي: **المحادثات** (اتصال فوري WebSocket بطبيعة مختلفة) و**الذكاء الاصطناعي** (تتغير بسرعة وتكلفتها بالاستخدام).

## البدائل
| البديل | سبب الرفض الآن |
|---|---|
| Microservices كاملة | تعقيد نشر وتتبّع أخطاء وأمان، وذاكرة أكبر لكل خدمة، ومطوّر واحد، وحمل صغير |
| Monolith بلا تقسيم داخلي | يصعّب الفصل لاحقًا |

## النتائج
- (+) تشغيل أسرع للمرحلة 1، وتكلفة استضافة أقل.
- (+) حدود الوحدات تسهّل الفصل لاحقًا.
- (-) التطبيق يُنشر كله مع كل تغيير.
- (-) يجب الانضباط: وحدة لا تصل لجداول وحدة أخرى إلا عبر Service.

## متى نراجع القرار؟
إذا ظهر حمل فعلي على المحادثات، أو دخل أكثر من مطوّر، أو احتاجت وحدة نشرًا مستقلًا.
